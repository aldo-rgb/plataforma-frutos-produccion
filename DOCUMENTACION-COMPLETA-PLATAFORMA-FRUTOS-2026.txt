3.1 SISTEMA LOBO SOLITARIO (Completado ✅)
--------------------------------------------------------------------------------

**Descripción:** Programa individual de 63 días (9 semanas) sin visión 
organizacional.

**Características:**
- **Planes disponibles:**
  - STANDARD Bimestral: 18 sesiones, $1,499 MXN
  - STANDARD Anual: 108 sesiones, $14,999 MXN
  - PREMIUM Bimestral: 18 sesiones, $2,499 MXN
  - PREMIUM Anual: 108 sesiones, $19,999 MXN

**Flujo implementado:**
1. Usuario va a `/dashboard/lobo-solitario/seleccionar-mentor`
2. Selecciona mentor de lista disponible
3. Sistema verifica si ya tiene paquete activo (prevención de duplicados ✅)
4. Usuario selecciona plan (STANDARD/PREMIUM) y frecuencia (BIMESTRAL/ANUAL)
5. Integración con Stripe para pago
6. Tras pago exitoso, crea `MentorPackageOrder` con status COMPLETED
7. Crea `PackageSessionCredits` con sesiones correspondientes
8. Redirecciona a `/dashboard/program/enroll?action=select-mentor`
9. Usuario agenda sus 2 sesiones semanales fijas

**Archivos clave:**
/app/dashboard/lobo-solitario/seleccionar-mentor/page.tsx
/app/api/lobo-solitario/crear-paquete/route.ts
/app/api/lobo-solitario/verificar-paquete-activo/route.ts
/app/api/lobo-solitario/create-checkout-session/route.ts

**Estado actual:**
- ✅ Prevención de compras duplicadas (backend + frontend)

}

5.4 Cálculo de Duración de Programas
--------------------------------------------------------------------------------

// Lobo Solitario
if (packageCredits) {
  totalWeeks = 9;
  totalCalls = packageCredits.totalSessions; // 18 o 108
}

// Programa con fechas explícitas
else if (enrollment.cycleStartDate && enrollment.cycleEndDate) {
  const diffInDays = Math.ceil(
    (endDate.getTime() - startDate.getTime()) / (1000 * 60 * 60 * 24)
  );
  totalWeeks = Math.ceil(diffInDays / 7);
  totalCalls = totalWeeks * 2;
}

// Por tipo de ciclo
else {
  switch(enrollment.cycleType) {
    case 'INTENSIVE_17_WEEKS': 
      totalWeeks = 17; totalCalls = 34; break;
    case 'INTENSIVE_6_MONTHS': 
      totalWeeks = 26; totalCalls = 52; break;
    case 'SOLO': 
      totalWeeks = 8; totalCalls = 16; break;
    default: 
      totalWeeks = 8; totalCalls = 16;
  }
}

Código de detección de enmascaramiento:
```typescript
const isMaskedValue = (value: string | null | undefined): boolean => {
  if (!value) return true;
  if (value.includes('*') || value.includes('•') || value.includes('·')) return true;
  const chars = value.split('');
  const charCount = chars.reduce((acc, char) => {
    acc[char] = (acc[char] || 0) + 1;
    return acc;
  }, {} as Record<string, number>);
  const maxCount = Math.max(...Object.values(charCount));
  if (maxCount > value.length * 0.5 && value.length > 10) return true;
  return false;
};
```

10. PAYMENT GATEWAY - FIX CONSTRAINT ÚNICO (CAUSA RAÍZ)
================================================================================

Problema raíz identificado:
- La base de datos tenía: organizationId Int @unique
- El schema de Prisma tenía: @@unique([organizationId, provider])
- Discrepancia causaba que solo se pudiera tener UNA pasarela por organización

Solución aplicada (sin pérdida de datos):
```sql
-- Eliminar constraint antiguo
ALTER TABLE "PaymentGatewayConfig" 
  DROP CONSTRAINT IF EXISTS "PaymentGatewayConfig_organizationId_key";

-- Crear nuevo constraint compuesto
ALTER TABLE "PaymentGatewayConfig" 
  ADD CONSTRAINT "PaymentGatewayConfig_organizationId_provider_key" 
  UNIQUE ("organizationId", "provider");
```

Archivo de migración creado:
- prisma/migrations/20260226_fix_payment_gateway_constraint/migration.sql

Resultado:
- ✅ 2 registros existentes conservados
- ✅ Ahora se pueden tener múltiples proveedores (Stripe + MercadoPago) por org
- ✅ El constraint permite: una config por combinación (organizationId, provider)

LECCIÓN IMPORTANTE:
- Siempre verificar que el schema de Prisma esté sincronizado con la BD real
- Usar `npx prisma db pull --print` para ver el estado real de la BD
- Las migraciones manuales deben documentarse en prisma/migrations/

```typescript
// Imports necesarios
import { useSearchParams } from 'next/navigation';

// Estado del filtro
const searchParams = useSearchParams();
const areaParam = searchParams.get('area');
const [areaFilter, setAreaFilter] = useState<string | null>(areaParam);

// Mapeo de área key a valores posibles en el campo area de las tareas
const areaKeyToAreaValues: Record<string, string[]> = {
  'finanzas': ['Finanzas', 'finanzas', '💰 Finanzas'],
  'relaciones': ['Relaciones', 'relaciones', '❤️ Relaciones'],
  'talentos': ['Talentos', 'talentos', '🎯 Talentos'],
  'pazMental': ['Paz Mental', 'pazMental', 'paz_mental', '🧘 Paz Mental'],
  'ocio': ['Ocio', 'ocio', '🎮 Ocio'],
  'salud': ['Salud', 'salud', '💪 Salud'],
  'servicioTrans': ['Servicio Transformacional', 'servicioTrans', ...],
  'servicioComun': ['Servicio Comunitario', 'servicioComun', ...],
};

// Función de filtrado
const filterTasksByArea = (taskList: Task[]) => {
  if (!areaFilter) return taskList;
  const validAreas = areaKeyToAreaValues[areaFilter] || [areaFilter];
  return taskList.filter(task => 
    validAreas.some(areaValue => 
      task.area?.toLowerCase().includes(areaValue.toLowerCase())
    )
  );
};

// Aplicar a las tareas
const filteredTasks = filterTasksByArea(tasks);
const filteredTareasRetrasadas = filterTasksByArea(tareasRetrasadas);
```

```typescript
// Nueva función canUseRole para validar permisos
const canUseRole = (role: string): boolean => {
  if (role === 'COORDINATOR_BASIC') return !!(usuario.esCoordinadorBasico || usuario.esCoordinador);
  if (role === 'COORDINATOR_ADVANCED') return !!(usuario.esCoordinadorAvanzado || usuario.esCoordinador);

  if (role === 'MENTOR') return !!(usuario.esMentor);
  if (role === 'LIDER') return !!(usuario.esLider);
  return role === usuario.rol;
};

// Al cargar activeRole de localStorage, validar
const savedRole = localStorage.getItem('activeRole');
if (savedRole && canUseRole(savedRole)) {
```

```
COMBO_FULL:   basePrice=$25,000
```

13.2 Upgrade de Básico a Avanzado (/dashboard/upgrade-advanced)
--------------------------------------------------------------------------------

El sistema detecta el "panorama" del usuario:

PANORAMA 1: BASICO_EN_CURSO
- Usuario está cursando activamente el Básico
- Tiene acceso a PRECIOS PROMOCIONALES
- Opciones disponibles:

  A) Solo Avanzado (ADVANCED_PROMO)
     - Precio: prices.ADVANCED (promo)
     - Precio tachado: prices.ADVANCED_BASE

  B) Combo Avanzado + PL (COMBO_BASE) ⭐ MEJOR VALOR
     - Precio: prices.COMBO_BASE
     - Ahorro: (ADVANCED_BASE + PL_BASE) - COMBO_BASE

  C) Apartado
     - Hoy paga: prices.COMBO (combo promo)
     - Después paga: prices.PL (PL promo)
     - Obtiene precio de combo base asegurado

PANORAMA 2: BASICO_COMPLETADO
- Usuario terminó el Básico (trainingStatus = COMPLETED)
- Solo acceso a PRECIOS BASE
- Opciones disponibles:

  A) Solo Avanzado (ADVANCED_BASE)
     - Precio: prices.ADVANCED_BASE

  B) Combo Avanzado + PL (COMBO_BASE) ⭐ RECOMENDADO
     - Precio: prices.COMBO_BASE
     - Ahorro: (ADVANCED_BASE + PL_BASE) - COMBO_BASE

--------------------------------------------------------------------------------
13.3 Upgrade de Avanzado a PL (/dashboard/upgrade-advanced)
--------------------------------------------------------------------------------

PANORAMA 3: AVANZADO_EN_CURSO
- Usuario está cursando el Avanzado
- YA PAGÓ el nivel Avanzado (precio promo = prices.ADVANCED)
- Quiere inscribirse a PL

FÓRMULAS DE CÁLCULO (DINÁMICAS por organización):

  A) Opción 1: Apartar Lugar (PL_APARTADO)
     - Ya pagaste (Avanzado): prices.ADVANCED
     - Paga ahora: prices.PL - prices.ADVANCED
     - Total apartado: prices.PL
     - Restante (antes del PL): prices.COMBO - prices.PL

  B) Opción 2: Completar COMBO (PL_COMPLETO) ⭐ RECOMENDADO
     - Ya pagaste (Avanzado): prices.ADVANCED
     - Paga ahora y completa: prices.COMBO - prices.ADVANCED
     - COMBO Total: prices.COMBO

EJEMPLO CON PRECIOS DE OAXACA:
```
ADVANCED promo = $5,500
PL promo = $6,000
COMBO promo = $6,500

Opción 1 - Apartar:
  Ya pagaste: $5,500
  Paga ahora: $6,000 - $5,500 = $500
  Total apartado: $6,000
  Restante: $6,500 - $6,000 = $500

Opción 2 - Completar COMBO:

  Paga ahora: $6,500 - $5,500 = $1,000
```

14.5 FLUJOS DE PAGO PARA NIVEL AVANZADO (Marzo 2026)
--------------------------------------------------------------------------------

La API /api/treasury/register-advanced maneja múltiples tipos de pago para 
inscripciones en Avanzado y combos. Los precios se configuran en:
/dashboard/school-admin/precios

**Tabla de flujos:**

| priceType              | Monto típico | Qué hace                                      |
|------------------------|--------------|-----------------------------------------------|
| ADVANCED_PROMO         | $7,500       | Crea ADVANCED pagado completo                 |
| ADVANCED               | $9,500       | Crea ADVANCED pagado completo (precio base)   |
| ADVANCED_UPGRADE_PL    | $1,500       | Para quien YA pagó ADVANCED, aparta PL        |
| COMBO_ADV_PL           | $14,500      | Crea ADVANCED + PL pagados completos          |
| COMBO_ADV_PL_PAGO1     | $9,000*      | 1er pago combo: ADVANCED pagado + PL apartado |
| COMBO_ADV_PL_PAGO2     | $5,500*      | 2do pago combo: completa PL apartado → pagado |

* Los montos de PAGO1 y PAGO2 son configurables en DefaultPrice (campos pago1, pago2)

**Detalle de cada flujo:**

1. ADVANCED_PROMO / ADVANCED:
   - Crea vision_enrollment nivel ADVANCED con paymentStatus: 'PAID'
   - Crea Ticket nivel ADVANCED con status: 'ACTIVE'

2. ADVANCED_UPGRADE_PL:
   - Requiere: ticket ADVANCED existente
   - Suma $1,500 al amountPaid del ticket ADVANCED
   - Crea enrollment PL con enrollmentStatus: 'PENDING', paymentStatus: 'PARTIAL'
   - Crea ticket PL tipo 'APARTADO' con status: 'PENDING_PAYMENT'

3. COMBO_ADV_PL:
   - Crea ADVANCED completo (enrollment + ticket pagados)
   - Crea PL completo (enrollment + ticket pagados)

4. COMBO_ADV_PL_PAGO1 (Primer pago del combo):
   - Crea ADVANCED completo (enrollment + ticket pagados)
   - Crea PL como apartado:
     * enrollment: enrollmentStatus: 'PENDING', paymentStatus: 'PARTIAL'
     * ticket: type: 'APARTADO', status: 'PENDING_PAYMENT'
   - Deuda pendiente = precioCombo - montoPagado

5. COMBO_ADV_PL_PAGO2 (Segundo pago del combo - liquidación):
   - Requiere: ticket PL con status: 'PENDING_PAYMENT'
   - Actualiza ticket PL:
     * type: 'STANDARD', status: 'ACTIVE', paymentStatus: 'PAID'
   - Actualiza enrollment PL:
     * enrollmentStatus: 'ACTIVE', paymentStatus: 'PAID'

**Campos en DefaultPrice para pagos parciales:**
- pago1: Decimal? - Monto del primer pago (apartado)
- pago2: Decimal? - Monto del segundo pago (liquidación)

Estos se configuran solo para COMBO_ADV_PL en /dashboard/school-admin/precios

Esta API retorna los tickets del usuario para mostrar en el Quantum Wallet.

--------------------------------------------------------------------------------
18.1 Filtrado de Tickets (Feb 2026)
--------------------------------------------------------------------------------

Para evitar mostrar tickets obsoletos o irrelevantes, se agregó filtrado:

```typescript
const sevenDaysAgo = new Date();
sevenDaysAgo.setDate(sevenDaysAgo.getDate() - 7);

const tickets = await prisma.ticket.findMany({
  where: {
    ownerId: user.id,
    // Excluir tickets cancelados, expirados o transferidos
    status: {
      notIn: ['CANCELLED', 'EXPIRED', 'TRANSFERRED'],
    },
    // Mostrar solo tickets pagados, parciales, regalados, O pendientes recientes
    OR: [
      { paymentStatus: { in: ['PAID', 'PARTIAL', 'GIFT'] } },
      // Tickets pendientes solo si son recientes (últimos 7 días)
      {
        paymentStatus: { in: ['PENDING', 'UNPAID'] },
        createdAt: { gte: sevenDaysAgo },
      },
    ],
  },
  orderBy: [
    { level: 'desc' },  // PL primero, luego ADVANCED, luego BASIC
    { status: 'asc' },
    { createdAt: 'desc' },
  ],
});
```

Esto evita mostrar:
- Tickets CANCELLED, EXPIRED, TRANSFERRED
- Tickets PENDING/UNPAID con más de 7 días (abandonados)

Filtro de búsqueda (ejemplo para BASIC):

```typescript
const filteredBasicStudents = basicStudents.filter(s => {
  // Primero filtrar por asistencia según showAllBasic
  const attendanceMatch = showAllBasic ? true : s.attendanceStatus !== 'ATTENDED';
  if (!attendanceMatch) return false;
  
  // Luego filtrar por búsqueda si hay query
  if (!basicSearchQuery.trim()) return true;
  const query = basicSearchQuery.toLowerCase();
  const nombre = s.Usuario?.nombre?.toLowerCase() || '';
  const email = s.Usuario?.email?.toLowerCase() || '';
  const telefono = s.Usuario?.telefono?.toLowerCase() || '';
  return nombre.includes(query) || email.includes(query) || telefono.includes(query);
});
```

20. FILTRADO DE TICKETS USADOS Y EXPIRADOS
================================================================================

Se mejoró la API de my-tickets para no mostrar tickets ya utilizados o expirados.

--------------------------------------------------------------------------------
20.1 Filtro de Tickets con ATTENDED (28 Feb 2026)
--------------------------------------------------------------------------------

Archivo: /app/api/tickets/my-tickets/route.ts

Los tickets donde el usuario ya tiene `attendanceStatus: 'ATTENDED'` en el
enrollment correspondiente NO deben mostrarse (ya fueron "usados").

```typescript
// Obtener enrollments con ATTENDED para filtrarlos
const attendedEnrollments = await prisma.vision_enrollments.findMany({
  where: {
    userId: user.id,
    attendanceStatus: 'ATTENDED',
  },
  select: { visionId: true, level: true },
});

// Crear set para búsqueda rápida
const attendedSet = new Set(
  attendedEnrollments.map(e => `${e.visionId}-${e.level}`)
);

// Filtrar tickets
const filteredTickets = tickets.filter(ticket => {
  const key = `${ticket.visionId}-${ticket.level}`;
  return !attendedSet.has(key);  // Excluir si ya tiene ATTENDED
});
```

--------------------------------------------------------------------------------
20.2 Filtro de Tickets Expirados (28 Feb 2026)
--------------------------------------------------------------------------------

Los tickets cuya visión ya terminó también deben excluirse:

```typescript
const now = new Date();

const finalTickets = filteredTickets.filter(ticket => {
  if (!ticket.Vision) return true;
  
  // Determinar fecha de fin según el nivel del ticket
  let endDate: Date | null = null;
  if (ticket.level === 'BASIC') {
    endDate = ticket.Vision.endDate;
  } else if (ticket.level === 'ADVANCED') {
    endDate = ticket.Vision.advancedEndDate;
  } else if (ticket.level === 'PL') {
    endDate = ticket.Vision.plWeekend3EndDate;
  }
  
  // Si no hay fecha de fin, mostrar el ticket
  if (!endDate) return true;
  
  // Excluir si la fecha de fin ya pasó
  return endDate >= now;
});
```

21. BUG DE TICKETS ADVANCED DUPLICADOS (28 Feb 2026)
================================================================================

Se descubrió y corrigió un bug crítico que permitía a usuarios crear tickets
de ADVANCED duplicados cuando ya habían completado ADVANCED en otra visión.

--------------------------------------------------------------------------------
21.1 Usuarios Afectados
--------------------------------------------------------------------------------

9 usuarios de Oaxaca (org ID 5) que ya habían completado ADVANCED en Vision 5
(ID: 13) con status ATTENDED, recibieron erróneamente tickets y enrollments
de ADVANCED para Vision 6 (ID: 16) el 22 de febrero de 2026.

Usuarios: Dahirte (959), HugoAquino (206), Stephania (285), Edith (204),
Emma (169), Geovani (187), Ana Edith (186), Griselda (170), Gabriela (173)

Total afectado: ~$63,500 MXN en registros erróneos

--------------------------------------------------------------------------------
21.2 Causa Raíz
--------------------------------------------------------------------------------

BUG 1: redeemPaymentCode ignoraba el parámetro visionId

Archivo: /app/api/gift-codes/redeem/route.ts

```typescript
// ANTES (BUG):
const enrollment = await prisma.vision_enrollments.findFirst({
  where: { userId: user.id },  // ⚠️ NO usaba visionId
  ...
});
```

La función recibía `visionId` como parámetro pero lo ignoraba, buscando
cualquier enrollment del usuario sin filtrar por visión.

BUG 2: enroll-advanced no verificaba graduación previa

Archivo: /app/api/me/enroll-advanced/route.ts

```typescript
// ANTES (BUG):
let existingAdvancedEnrollment = await prisma.vision_enrollments.findFirst({
  where: {
    userId: userId,
    visionId: visionId,  // Solo verificaba la visión solicitada
    level: 'ADVANCED',
  },
});
```

Solo verificaba si el usuario tenía enrollment ADVANCED en la visión 
específica solicitada, pero NO verificaba si ya había completado (ATTENDED) 
ADVANCED en otra visión anterior.

--------------------------------------------------------------------------------
21.3 Correcciones Aplicadas
--------------------------------------------------------------------------------

FIX 1: redeemPaymentCode ahora respeta visionId

```typescript
// DESPUÉS:
let targetVisionId: number | null = null;

if (visionId) {
  targetVisionId = parseInt(String(visionId));
} else if (paymentCode.visionId) {
  targetVisionId = paymentCode.visionId;
}

// Buscar solo en visiones activas (no ATTENDED)
enrollment = await prisma.vision_enrollments.findFirst({
  where: { 
    userId: user.id,
    visionId: targetVisionId,
    attendanceStatus: { notIn: ['ATTENDED'] }
  },
  ...
});
```

FIX 2: enroll-advanced valida graduación previa

```typescript
// DESPUÉS:
// Verificar si el usuario ya COMPLETÓ (ATTENDED) ADVANCED en CUALQUIER visión
if (!isPLOnlyPurchase) {
  const completedAdvanced = await prisma.vision_enrollments.findFirst({
    where: {
      userId: userId,
      level: 'ADVANCED',
      attendanceStatus: 'ATTENDED',
    },
    ...
  });

  if (completedAdvanced) {
    return NextResponse.json({
      success: false, 
      error: `Ya completaste el entrenamiento Avanzado en ${visionName}...`
    });
  }
}
```
