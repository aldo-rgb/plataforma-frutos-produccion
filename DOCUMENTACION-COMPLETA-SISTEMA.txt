### Modelos Principales

#### 1. **Usuario** (Tabla central del sistema)
```prisma
model Usuario {
  id                    Int       @id @default(autoincrement())
  email                 String    @unique
  nombre                String
  password              String
  rol                   Rol       // ADMIN, SCHOOL_ADMIN, COORDINADOR, etc.
  tier                  Tier?     // STANDARD, PREMIUM
  organizationId        Int?
  isActive              Boolean   @default(true)
  
  // Relaciones importantes
  Organization          Organization? @relation("Usuario_organizationIdToOrganization")
  LicenseAssignments    LicenseAssignment[] @relation("LicenseAssignment_userIdToUsuario")
  VisionParticipante    VisionParticipante[]
  VisionGameChanger     VisionGameChanger[]
}

enum Rol {
  ADMIN
  SCHOOL_ADMIN
  COORDINADOR
  COORDINATOR_BASIC
  COORDINATOR_ADVANCED
  TRAINER
  GAMECHANGER
  PARTICIPANTE
  MENTOR
  LOBO_SOLITARIO
}

enum Tier {
  STANDARD
  PREMIUM
}
```

```prisma
model MasterOrganization {

```

#### 4. **Vision** (Programas/Ciclos)
```prisma
model Vision {
  id                    Int       @id @default(autoincrement())
  nombre                String
  descripcion           String?
  organizationId        Int
  coordinadorId         Int?
  isActive              Boolean   @default(true)
  maxParticipantes      Int       @default(100)
  
  // Fechas BÁSICO
  startDate             DateTime
  endDate               DateTime
  
  // Fechas AVANZADO
  advancedStartDate     DateTime?
  advancedEndDate       DateTime?
  
  // Fechas LIDERATO (PL) - 3 fines de semana
  plWeekend1StartDate   DateTime?
  plWeekend1EndDate     DateTime?
  plWeekend2StartDate   DateTime?
  plWeekend2EndDate     DateTime?
  plWeekend3StartDate   DateTime?
  plWeekend3EndDate     DateTime?
  
  // Niveles habilitados
  enabledLevels         Level[]   // ['BASIC', 'ADVANCED', 'PL']
  
  Organization          Organization @relation(fields: [organizationId])
  VisionParticipante    VisionParticipante[]
  VisionGameChanger     VisionGameChanger[]
  vision_enrollments    vision_enrollments[]
}

enum Level {
  BASIC
  ADVANCED
  PL
}
```

#### 5. **vision_enrollments** (Inscripciones por nivel)
```prisma
model vision_enrollments {
  id              Int       @id @default(autoincrement())
  visionId        Int
  userId          Int
  level           Level     // BASIC, ADVANCED, PL
  enrolledAt      DateTime  @default(now())
  completedAt     DateTime?
  status          String?   // 'ACTIVE', 'COMPLETED', 'DROPPED'
  
  Vision          Vision    @relation(fields: [visionId])
  Usuario         Usuario   @relation(fields: [userId])
  
  @@unique([visionId, userId, level])
}
```

#### 6. **VisionParticipante** (Participantes asignados)

```prisma
model VisionParticipante {
```

#### 7. **VisionGameChanger** (Game Changers por nivel)

```prisma
model VisionGameChanger {
```

#### 8. **License** (Licencias generadas)
```prisma
model License {

  isActive        Boolean   @default(true)
  isMasterCode    Boolean   @default(false)
  organizationId  Int
  expiresAt       DateTime?
  
  Organization    Organization @relation(fields: [organizationId])
}
```

#### 9. **LicenseAssignment** (Asignaciones de licencias a usuarios)
```prisma
model LicenseAssignment {
  id              Int       @id @default(autoincrement())
  userId          Int
  organizationId  Int
  visionId        Int?
  licenseCode     String
  assignedBy      Int
  assignedAt      DateTime  @default(now())
  isActive        Boolean   @default(false)
  activatedAt     DateTime?
  expiresAt       DateTime?
  notes           String?
  
  Usuario         Usuario   @relation("LicenseAssignment_userIdToUsuario", fields: [userId])
  Organization    Organization @relation(fields: [organizationId])
  Vision          Vision?   @relation(fields: [visionId])
  AssignedBy      Usuario   @relation("LicenseAssignment_assignedByToUsuario", fields: [assignedBy])
}
```

#### 10. **SchoolCredit** (Control de licencias por organización)
```prisma
model SchoolCredit {

  totalAllocated  Int       @default(0)  // Licencias ya asignadas
  isActive        Boolean   @default(true)
  
  Organization    Organization @relation(fields: [organizationId])
  
  // Disponibles = totalPurchased - totalAllocated
}
```

### Estructura Implementada

**BÁSICO (BASIC)**
- Duración: startDate → endDate
- Participantes inscritos en vision_enrollments con level='BASIC'
- Game Changers asignados en VisionGameChanger con level='BASIC'
- Coordinador: basicCoordinatorId
- Trainer: basicTrainerId

**AVANZADO (ADVANCED)**
- Duración: advancedStartDate → advancedEndDate
- Participantes inscritos con level='ADVANCED'
- Game Changers con level='ADVANCED'
- Coordinador: advancedCoordinatorId
- Trainer: advancedTrainerId

**LIDERATO (PL - Program Leadership)**
- 3 Fines de semana:
  - Weekend 1: plWeekend1StartDate → plWeekend1EndDate
  - Weekend 2: plWeekend2StartDate → plWeekend2EndDate
  - Graduación: plWeekend3StartDate → plWeekend3EndDate
- Participantes inscritos con level='PL'
- Game Changers con level='PL'
- Coordinador: plCoordinatorId
- 3 Trainers (uno por fin de semana): plTrainer1Id, plTrainer2Id, plTrainer3Id

### 1. Sistema Multi-Organización ✅

**Signup Flow con Master/Child Organizations:**

Archivo: /app/auth/signup/page.tsx
- URL: /auth/signup?org=1 (donde 1 es el ID de una Organization)
- Proceso:
  1. Llama a /api/public/organization/[code] con el ID
  2. API busca la Organization y su MasterOrganization
  3. Retorna: { masterOrganization, childOrganizations[] }
  4. UI muestra logo de MasterOrganization como título
  5. Muestra cards de childOrganizations para seleccionar sede
  6. Al seleccionar sede: llama a /api/public/organization/[orgId]/next-vision
  7. Muestra próxima visión BASIC activa de esa sede
  8. Registra usuario con organizationId de la sede seleccionada

                            💡 NOTAS IMPORTANTES

- **SchoolCredit:** Controla licencias disponibles. NO crear créditos 
  manualmente sin orden real.

- **visionId en licencias:** Siempre incluir cuando se conoce la visión.

- **Niveles:** BASIC es obligatorio, ADVANCED y PL son opcionales según 
  enabledLevels.

- **Game Changers:** SIEMPRE deben tener licencia STANDARD activa al crearse.

- **MasterOrganization vs Organization:** NO confundir las tablas.
