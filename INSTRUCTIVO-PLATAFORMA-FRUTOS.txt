👥 TIPOS DE USUARIO (CRÍTICO - MEMORIZAR)
================================================================================

TIPO 1: LOBO SOLITARIO
-----------------------
- Identificación: NO tiene vision_enrollments NI VisionParticipante
- Acceso: COMPLETO a todo el software
- Programa de Seguimiento: ✅ SÍ tiene acceso
- Paga individualmente, no pertenece a ninguna escuela/visión

TIPO 2: VISION ENROLLED (Acceso Progresivo)
-------------------------------------------
- Identificación: Tiene registro en vision_enrollments con enrollmentStatus: 'ENROLLED'
- Se crea cuando: Usuario se registra vía /api/auth/register con visionId
- Niveles: BASIC → ADVANCED → PL
- Acceso BASIC: Ranking, Quantum, Llamadas Mentor
- Acceso ADVANCED: + Carta, Metas
- Acceso PL: + Tareas, Evidencias, Programa de Seguimiento (completo)

TIPO 3: VISION PARTICIPANTE (Liderato Directo)
----------------------------------------------
- Identificación: Tiene registro en VisionParticipante (sin enrollment)
- Se crea cuando: Coordinador agrega manualmente al usuario
- Acceso: COMPLETO (igual que Lobo Solitario)
- Programa de Seguimiento: ✅ SÍ tiene acceso
- Típicamente: Líderes, invitados especiales, usuarios que entran directo a Liderato

🗄️ MODELOS DE BASE DE DATOS PRINCIPALES (PRISMA)

// Usuario principal
model Usuario {
  id                    Int
  email                 String @unique
  nombre                String
  rol                   String // PARTICIPANTE, COORDINADOR, MENTOR, ADMIN, SCHOOL_ADMIN
  organizationId        Int?
  tier                  String // FREE, STANDARD, PREMIUM
  suscripcion           String?
  referralCode          String? @unique
  invitedBy             Int?
  currentVisionLevel    String? // BASIC, ADVANCED, PL
  assignedMentorId      Int?
  mentorId              Int?
}

// Enrollment progresivo en Vision (FUENTE DE ACCESO PROGRESIVO)
model vision_enrollments {
  id                Int @id @default(autoincrement())
  userId            Int
  visionId          Int
  coordinatorId     Int?
  level             String // BASIC, ADVANCED, PL
  enrollmentStatus  String // ENROLLED, COMPLETED, DROPPED
  enrolledAt        DateTime?
  completedAt       DateTime?
  graduatedAt       DateTime?
}

// Participante agregado por coordinador (ACCESO COMPLETO)
model VisionParticipante {
  id              Int @id @default(autoincrement())
  visionId        Int
  participanteId  Int
  gameChangerId   Int?
  createdAt       DateTime
}

// Formulario médico
model MedicalForm {
  id                      Int @id @default(autoincrement())
  odooContactId           String?
  userId                  Int @unique
  hasCurrentIllness       Boolean
  currentIllnessDetails   String?
  hasCurrentTreatment     Boolean
  currentTreatmentDetails String?
  takesMedication         Boolean
  medicationDetails       String?
  hasAllergies            Boolean
  allergiesDetails        String?
  hadSurgery              Boolean
  surgeryDetails          String?
  emergencyContactName    String
  emergencyContactPhone   String
  emergencyContactRelation String
  signatureData           String // Base64 de la firma
  consentAccepted         Boolean
  submittedAt             DateTime
  reviewedAt              DateTime?
  reviewedBy              Int?
  isActive                Boolean @default(true)
  createdAt               DateTime @default(now())
  updatedAt               DateTime @updatedAt
}

// Tickets para eventos
model Ticket {
  id              Int @id @default(autoincrement())
  eventId         Int
  ownerId         Int
  referrerId      Int?
  status          String // RESERVED, PAID, USED, CANCELLED
  qrCode          String @unique
  pricePaid       Decimal
  createdAt       DateTime
}

// Gift Codes (Códigos de Regalo)
model GiftCode {
  id              Int @id @default(autoincrement())
  code            String @unique
  type            String // FULL_PAYMENT, PARTIAL, BALANCE
  value           Decimal?
  percentage      Int?
  maxUses         Int @default(1)
  currentUses     Int @default(0)
  validFrom       DateTime
  validUntil      DateTime?
  organizationId  Int
  createdBy       Int
  isActive        Boolean @default(true)
}

// Vision (Grupo/Cohorte)
model Vision {
  id              Int @id @default(autoincrement())
  nombre          String
  organizationId  Int
  coordinadorId   Int?
  startDate       DateTime?
  endDate         DateTime?
  maxParticipantes Int?
}

// Carta de Frutos
model CartaFrutos {
  id              Int @id @default(autoincrement())
  usuarioId       Int @unique
  status          String // DRAFT, PENDING_REVIEW, APPROVED, REJECTED
  mentorId        Int?
  finanzasMeta    String?
  relacionesMeta  String?
  talentosMeta    String?
  pazMentalMeta   String?
  ocioMeta        String?
  saludMeta       String?
  servicioComunMeta String?
}

PARA PROTEGER UNA PÁGINA NUEVA:
-------------------------------
'use client';

import { ProtectedModulePage } from '@/components/ui/LockedModuleOverlay';

export default function MiPaginaProtegida() {
  return (
    <ProtectedModulePage moduleKey="tareas">
      {/* Contenido de la página */}
    </ProtectedModulePage>
  );
}

MÓDULOS DISPONIBLES PARA moduleKey:
-----------------------------------

- metas
- tareas
- evidencias
- quantum
- llamadasMentor
- disciplina

PARA VERIFICAR ACCESO EN UN COMPONENTE:
---------------------------------------
import { useVisionAccess } from '@/contexts/VisionAccessContext';

function MiComponente() {
  const { canAccess, userType, currentLevel, isVisionParticipante } = useVisionAccess();
  
  if (!canAccess('tareas')) {
    return <div>No tienes acceso a esta función</div>;
  }
  
  return <div>Contenido...</div>;
}

📝 NOTAS DE ESTILO DE CÓDIGO
================================================================================

1. Imports de Prisma: 
   import { prisma } from '@/lib/prisma';

2. Sesión de NextAuth: 
   import { getServerSession } from 'next-auth';
   import { authOptions } from '@/lib/auth';
   const session = await getServerSession(authOptions);

3. ID de usuario (siempre parsear):
   const userId = typeof session.user.id === 'string' 
     ? parseInt(session.user.id) 
     : session.user.id;

4. Componentes cliente:
   'use client'; // Primera línea del archivo

5. Relaciones Prisma con nombres largos:
   vision_enrollments_vision_enrollments_userIdToUsuario

6. Respuestas de API:
   return NextResponse.json({ success: true, data: ... });
   return NextResponse.json({ success: false, error: '...' }, { status: 400 });
