================================================================================
🏗️ ARQUITECTURA GENERAL DE LA APLICACIÓN
================================================================================

STACK TECNOLÓGICO
--------------------------------------------------------------------------------
- Framework: Next.js 16.1.1 con Turbopack
- Base de Datos: PostgreSQL con Prisma ORM
- Autenticación: NextAuth.js
- Estilización: Tailwind CSS
- Lenguaje: TypeScript
- Real-time: Socket.IO
- Pagos: Stripe (pagos individuales) + Sistema B2B de licencias
- Deployment: Vercel

ESTRUCTURA DE CARPETAS PRINCIPAL
--------------------------------------------------------------------------------
plataforma-frutos-FINAL/
├── app/                          # App Router de Next.js
│   ├── api/                      # API Routes

1. USUARIO (MODELO CENTRAL)
--------------------------------------------------------------------------------
model Usuario {
  id                    Int       @id @default(autoincrement())
  nombre                String
  email                 String    @unique
  password              String
  imagen                String?
  rol                   Rol       @default(PARTICIPANTE)
  puntosCuanticos       Int       @default(0)
  isActive              Boolean   @default(true)
  tier                  Tier      @default(FREE)
  
  // Relaciones de organización (B2B)
  organizationId        Int?
  organization          Organization? @relation("OrganizationMembers")
  communityOrganizationId Int?
  communityOrganization Organization? @relation("CommunityMembers")
  
  // Relaciones de mentoría
  mentorId              Int?
  mentor                Usuario?  @relation("MentorParticipantes")
  mentorados            Usuario[] @relation("MentorParticipantes")
  assignedMentorId      Int?
  assignedMentor        Usuario?  @relation("AssignedMentor")
  assignedStudents      Usuario[] @relation("AssignedMentor")
  
  // Gamificación
  experienciaXP         Int       @default(0)
  nivelActual           Int       @default(1)
  rangoActual           String    @default("NOVATO")
  puntosGamificacion    Int       @default(0)
  completionStreak      Int       @default(0)
  lastCompletionDate    DateTime?
  
  // Perfil de mentor
  perfilMentor          PerfilMentor?
  
  // Carta F.R.U.T.O.S.
  cartasFrutos          CartaFrutos[]
  
  // Evidencias
  evidencias            EvidenciaAccion[]
  
  // Muchas más relaciones...
}

enum Rol {
  PARTICIPANTE
  MENTOR
  LIDER
  GAME_CHANGER
  COORDINADOR
  DIRECTOR
  SCHOOL_ADMIN
  ADMIN
  ADMINISTRADOR
}

enum Tier {
  FREE
  STANDARD
  PREMIUM
  ELITE
}

3. LICENSE (SISTEMA DE LICENCIAS B2B)

model License {
  id              Int          @id @default(autoincrement())
  code            String       @unique
  tier            Tier         @default(STANDARD)
  organizationId  Int
  organization    Organization @relation(fields: [organizationId])
  isActive        Boolean      @default(true)
  createdAt       DateTime     @default(now())
}

model LicenseAssignment {
  id              Int          @id @default(autoincrement())
  licenseCode     String
  usuarioId       Int          @unique
  usuario         Usuario      @relation("UserLicense")
  organizationId  Int
  organization    Organization @relation(fields: [organizationId])
  assignedAt      DateTime     @default(now())
  activatedAt     DateTime?
  isActive        Boolean      @default(true)
}

model LicenseOrder {
  id              String            @id @default(cuid())
  organizationId  Int
  organization    Organization      @relation(fields: [organizationId])
  quantity        Int
  tier            Tier
  amount          Float
  status          LicenseOrderStatus @default(PENDING)
  paymentMethod   String?
  paymentUrl      String?
  receiptUrl      String?
  createdAt       DateTime          @default(now())
  paidAt          DateTime?
}

enum LicenseOrderStatus {
  PENDING      // Esperando pago
  PROCESSING   // Pago en revisión
  PAID         // Pagado y licencias activadas
  CANCELLED    // Cancelado
}

model CartaFrutos {

  relacionesAvance          Int       @default(0)

  relacionesDeclaracion     String?
  relacionesDeclaracionStatus DeclaracionStatus @default(PENDIENTE)

  updatedAt                 DateTime  @updatedAt

model AdminTask {

📊 FLUJOS PRINCIPALES DE LA APLICACIÓN
================================================================================

FLUJO DE REGISTRO Y ONBOARDING
--------------------------------------------------------------------------------
1. Usuario se registra con email/password
2. Sistema asigna rol por defecto: PARTICIPANTE
3. Tier por defecto: FREE
4. Si tiene código de licencia → valida y asigna tier
5. Si está en organización → asigna a organización
6. Redirect a /dashboard
7. Si requirePasswordChange → forzar cambio de contraseña

FLUJO DE CARTA F.R.U.T.O.S.
--------------------------------------------------------------------------------
1. Usuario crea carta (estado: BORRADOR)
2. Define metas en cada área
3. Programa días de ejecución
4. Envía a revisión (estado: EN_REVISION)
5. Si es FREE: auto-aprobación (estado: APROBADA)
6. Si es de pago:
   - Mentor revisa y aprueba/rechaza
   - Si rechaza → CAMBIOS_REQUERIDOS
   - Si aprueba → espera coordinador
   - Coordinador aprueba → APROBADA
7. Carta aprobada → puede subir evidencias

FLUJO DE EVIDENCIAS
--------------------------------------------------------------------------------
1. Usuario sube foto + descripción
2. Estado: PENDIENTE
3. Mentor revisa
4. Si aprueba:
   - Marca como APROBADA
   - Puede marcar como High Quality
   - Si usuario es FREE: +XP (sin puntos cuánticos)
   - Si usuario de pago: +XP + puntos cuánticos
5. Si rechaza:
   - Marca como RECHAZADA
   - Selecciona tipo de rechazo
   - Usuario puede reintentar (máx 3 veces)
   - Tercer rechazo → rechazo definitivo

FLUJO DE LICENCIAS (B2B)
--------------------------------------------------------------------------------
1. Director crea orden de licencias
2. Selecciona cantidad y tier
3. Sistema genera orden (estado: PENDING)
4. Director realiza transferencia bancaria
5. Director sube comprobante de pago
6. Estado cambia a: PROCESSING
7. Admin revisa comprobante
8. Si aprueba:
   - Genera códigos de licencia
   - Marca orden como PAID
   - Notifica al director
9. Director asigna licencias a usuarios
10. Usuario activa licencia → cambia tier

FLUJO DE MENTORÍA GRUPAL (DISCIPLINA)
--------------------------------------------------------------------------------
1. Participante se inscribe a programa
2. Selecciona mentor
3. Selecciona tipo de ciclo (4 o 8 semanas)
4. Sistema bloquea créditos de llamadas
5. Sistema genera fechas de llamadas
6. Participante agenda horario para cada llamada
7. Mentor confirma o reprograma
8. Al completar llamada:
   - Marca como COMPLETED
   - Libera crédito usado
   - Genera feedback
9. Al finalizar ciclo → certificado

FLUJO DE TAREAS EXTRAORDINARIAS
--------------------------------------------------------------------------------
1. Admin/Coordinador crea tarea
2. Define categoría y recompensas
3. Define asignación (todos, visión específica, rol)
4. Define fechas de disponibilidad
5. Usuarios ven tarea en dashboard
6. Usuario sube evidencia (si requiere)
7. Estado: PENDING
8. Revisor aprueba/rechaza
9. Si aprueba:
   - Otorga puntos y XP
   - Incrementa contador de completaciones
   - Si alcanza límite → desactiva tarea
